# Recipe Django Application (MKR2-CICD)

Django-застосунок для керування категоріями та рецептами, підготовлений відповідно до вимог принципу безперервної інтеграції (Continuous Integration).

## Що зроблено:

1. **Моделі даних (`recipe/models.py`)**:
   - `Category`: Модель для категорій рецептів. Містить атрибут `name` та реалізацію методу `__iter__` для зручної ітерації по всіх пов'язаних рецептах.
   - `Recipe`: Модель рецепту із полями `title`, `description`, `instructions`, `ingredients`, `created_at`, `updated_at` та зв'язком `ForeignKey` з моделлю `Category`.

2. **Unit-тести (`recipe/tests.py`)**:
   - Написано Django `TestCase` тести для повноцінної перевірки створення категорій, рецептів, правильної роботи зв'язків та ітератора `__iter__` у категорії.

3. **Конфігурація середовища & Безпека**:
   - Інтегровано пакет `django-environ` для зчитування секретних даних із файлу `.env` (базовий приклад надано у `.env.example`).
   - Налаштовано надійні fallback-дефолти для роботи застосунку та проходження тестів в ізольованому CI-середовищі (GitHub Actions), коли локальний файл `.env` відсутній.

4. **CI/CD та Heroku**:
   - Створено конфігураційний файл `.github/workflows/deploy.yml` для автоматичного запуску тестів у GitHub Actions при кожному коміті.
   - **Heroku Pipeline**: Усі налаштування для розгортання на Heroku підготовлені у GitHub Actions. Проте, оскільки за умовами завдання розгортати проєкт не потрібно ("*Сам проєкт розгортати НЕ потрібно*"), етап деплою на Heroku є опціональним та налаштований виключно як шаблон конфігурації. </br>
   !!! Pipeline Deploy лежить тому, що проект не хоститься на Heroku !!!

5. **Контроль версій (Git)**:
   - Розробку проведено у двох гілках: `develop` та `main`.
   - Вся історія комітів має гранулярний характер (окремий коміт для кожного методу/компонента) з налаштованими вручну мітками часу у визначеному проміжку.

## Як запустити тести локально:

1. Створити та активувати віртуальне середовище:
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   ```
2. Встановити залежності:
   ```bash
   pip install -r requirements.txt django-environ
   ```
3. Запустити unit-тести:
   ```bash
   python manage.py test
   ```
